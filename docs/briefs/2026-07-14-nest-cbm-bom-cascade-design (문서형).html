NEST CBM·BOM Cascade 설계 브리프 — 3문항 답변

NEST API 읽기전용 PoC 실측(96.9%)과 WMS Location 실사를 근거로, CBM 체인의 구조적 요구·NEST 데이터 요구사항·자재팀 위치 액션을 설계한다.

I요약 (3문항 → 3답변)핵심

아래 3문항에 대한 한 줄 답변을 먼저 제시하고, 각 답변의 근거는 Part 1~3에서 상세히 전개한다.

Q1
TMS Product 원본이 사실상 NEST 박스 CBM 등록이라면, 진짜 요구는 박스 CBM API 노출인가?
그렇다. TMS 조인(현재 96.9% 도달)은 과도기 경로이고, 구조적 요구 = NEST 박스 스펙의 API 노출 (additive /v1.x로 가능). 노출 시 TMS Product는 대사 대상으로 강등.
Q2
cascade 전개에 NEST가 더 줘야 하는 데이터는?
필수 2건(박스 스펙 노출·견적 버전 신호) + 권장 3건 + 선택 2건. PT 자재 BOM·치수·재고·실측 CBM은 NEST 영역이 아님 — WMS가 SSOT 유지. 미수용 시 fallback = 크로스워크 사본 큐레이션.
Q3

주문 등록 순간 발주 vs 거점간 이동(311) 분기 제안이 핵심. 3노드 네트워크(베스트원 버퍼 / 에이원 투입·임가공 / 외주 다영 등 동적 임가공지) 기준 S2.5 위치분기 레이어 설계. 선행 과제 3건 명시.

IIPart 1 — CBM 의존 체인: 진짜 요구는 "NEST 박스 CBM API 노출"

NEST 마스터 DB에서 TMS Product를 거쳐 cascade S5까지 이어지는 현재 체인을 그대로 따라가 본다.

1.1 현재 체인의 실체

NEST 마스터 DB                          ← 박스 스펙 "등록 원천" (사용자 확인)
  옵션 레벨: 박스명칭(특대형 등 5종 어휘) + 박스단위(개당, 예 0.0625)
  단품/키트 각각 별도 값 · MOQ · 견적 시점 차량 산정에 사용 중
      │
      │  [수기 사본 — drift 발생 지점]
      ▼
TMS Product 테이블                      ← cascade가 실제로 읽는 곳
  견적코드별 박스명칭 + 박스당 제품수 (+ formula CBM ~98% 공백 → 표준표 폴백)
      │
      ▼
cascade S5 출하 CBM 예측                ← 물리 굿즈 96.9% 도달 (PoC 실측)

사본 구조의 실증 (drift 증거)

  • 단품/키트 박스 스펙을 TMS는 이름 접미로 임시 분리 — LSPO 로고스트랩 파우치 (대형/100) vs LSPH 로고스트랩 파우치 (키트) (중대형/25). NEST는 같은 것을 옵션 레벨 구조로 관리.
  • WMS↔TMS 코드 불일치 보정용 하드코딩 alias 8건 + 사이즈군 4건 (product_alias.py, "사용자 확정 2026-06-16").
  • TMS Product의 박스 CBM formula 필드는 ~98%가 0 (박스사이즈 미입력) — 코드의 표준표(BOX_TYPE_TO_CBM_M3)가 사실상 권위.

1.2 결론 명제

TMS Product 조인은 과도기 경로다. 구조적 요구는 NEST 박스 CBM의 API 노출이다. Part 1 결론 명제

현재 API v1.0 응답에는 부피 재료가 0개 (수량·옵션명·키트구성뿐). 옵션 문자열(박스 사이즈 M)로 표준 부피를 추정하는 우회도 박스당 입수량이 없어 출하 박스 수를 못 센다 — 이 빠진 조각이 정확히 NEST 마스터의 "박스단위(개당)"이다.

1.3 노출 요구 스펙 초안 (NEST팀 전달용)

quoteGoods[] 각 항목에 additive 필드 추가 (하위호환 — /v1.x 배포 가능, 스키마 정책 §11 부합):

{
  "quoteGoodsInstanceId": "...",
  "goodsCode": "DRCG",
  "packaging": {
    "standalone": { "boxName": "특대형", "boxUnitPerPiece": 0.0625 },
    "inKit":      { "boxName": "특대형", "boxUnitPerPiece": 0.0625 }
  }
}
  • boxName: 마스터의 박스 명칭 (극소형/중형/중대형/대형/특대형)
  • boxUnitPerPiece: 마스터의 "박스단위(개당)" — 의미론 확인 필요: 박스당 제품수의 역수(0.0625=16개/박스)인지 서면 확인
  • standalone/inKit: 단품·키트 포장 구분 (마스터에 이미 분리 존재)

2.3 Fallback — 요구 미수용 시의 "다른 SSOT 방향"

  • 박스명칭·입수량을 WMS 크로스워크/ItemMaster에 사본 큐레이션 (기계 제안=미검증, 확정 승급=대사+안나 승인)
  • 장점: 런타임 TMS 의존 제거, 우리 통제권. 단점: 수기 관리 부담이 물류로 이전 — NEST 마스터와의 drift를 우리가 떠안음

IVPart 3 — 자재팀 위치 액션 설계 (베스트원/에이원)

PT 치수 입력으로 MRP·입하 CBM이 완결되는 시점을 가정하고, 그 다음 물류 액션 — 발주 vs 이동 분기 — 을 3노드 네트워크 기준으로 설계한다.

베스트원 (보관 버퍼)          에이원센터 (1차 투입 + ASSEMBLY)      외주 임가공지 (다영기획 등)

      │ ③ 보충 이동(311) ──────────→ │  │                                │
      │ ② 직입하 ────────────────────┼──┼────────────────────────────────┤

  • 임가공지는 프로젝트별 동적 — 에이원 지정 후 다영으로 변경되는 케이스 실존
  • 이동 패턴 3종: ① 에이원→다영 재이동 (투입했던 자재 회수 이동) ② 베스트원→다영 직입하 ③ 베스트원→에이원 보충
