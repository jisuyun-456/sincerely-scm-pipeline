BOM·CBM 데이터 기초 공동설계 — 킥오프 핸드오프

품질혁신파트(안나) × 물류파트 공식 협업 · 2026-06-24 킥오프

작성일2026.06.24 참여품질혁신파트(안나) × 물류파트 용도킥오프 공동 정렬 · 핸드오프 문서 작성물류파트 윤지수
DB 백엔드 잠정 · TBD
신규 SSOT의 DB 백엔드(Supabase 등)는 아직 미확정이다. 본 문서의 플랫폼 관련 내용은 전부 잠정(TBD) — 킥오프 이후 안나 주도 공동 결정 대상이다. 확정된 원칙은 "운영 데이터는 백엔드 선택과 무관하게 Airtable 유지" 하나뿐이다.

I결론 먼저 — 무엇을 하고 싶은가핵심

"프로젝트 등록 → 기사 운임마감까지 자동으로 흐르는 물류 프로세스를 구축한다." 이 킥오프의 결론

그러려면 맨 밑바닥 — 아이템 정체성 SSOT — 부터 새로 기초공사를 시작해야 한다. 그 위에 순서대로 쌓는다.

1 정체성 SSOT → 2 계층 → 3 BOM(소요량) → 4 CBM(부피) → 5 수량전파(cascade)
  • 물류가 혼자 테스트로 만든 cascade는 "이 최종 흐름이 실제로 가능하다"를 보여주는 증명 예시(프로토타입)일 뿐이다. 데이터 기초는 승윤, 안나님 의견을 반영한다.
  • 이 킥오프의 핵심 질문 = "어디서부터 SSOT를 잡고, 데이터 구조를 짜고, BOM·CBM을 쌓을 것인가" → 5단계 기초공사 순서(IV장)로 답한다.
오늘 반드시 닫을 것
로드맵 순서(VI장) + RACI(V장).

II배경 — 왜 지금인가

경영진이 BOM·CBM 공식 협업 + 안나-물류파트 공식 협업을 최종 승인했다.

현재 구조는 아래 순서 위에서 6개 모듈이 돌아간다.

SERPA 3.0 → sync → WMS/TMS(Airtable)
project (고객주문) → order → task (생산·임가공) → pkg (패키징) → movement (자재투입) → TMS (배송)

이 6개 모듈은 Airtable 네이티브 링크가 아니라 텍스트 키(프로젝트코드·아이템코드·파츠코드)로만 위태롭게 이어져 있다. 그 결과 아래 세 가지 구조적 문제가 발생한다.

구조적 문제

문제
현상
BOM 마스터 부재
구조화된 자재명세 테이블 0개. 사람이 프로젝트마다 BOM 로직을 머릿속으로 재실행.
CBM 마스터 반쪽
신뢰 가능한 부피 숫자가 TMS Product에만. WMS/MES는 텍스트 규격 → 부피 계산 불가.
정체성 약점
굿즈명 텍스트 조인 성공률 53% — 이름이 조금만 달라도 연결이 끊긴다.
정체성·계층(무엇인가)은 안나 도메인, BOM·CBM·전파(얼마나·어떤 부피로 흐르는가)는 물류 도메인. 기초부터 함께 세울 최적 타이밍

III최종 비전 — cascade 예시로

한 프로젝트가 등록되는 순간 아래가 자동으로 흐른다. 물류 프로토타입이 이미 시연했으며, 아래는 2026-06-22 dry-run 스냅샷이다.

Cascade 플로우 — PNA51684 (보령 프로젝트)
# 입력 주문
[WMS order]   PNA51684 · 쇼핑백/G형박스/눈마사지기/미르텀블러 각 100 + 키트포장 100

# S0 ~ S7 자동 전파
[S0 감지]     (PNA, 굿즈) 단위 신규 주문 감지
[S1 키해소]   PT#### ↔ WMS 아이템코드 ↔ TMS 견적코드 크로스워크 정합
[S2 MRP]      자재 전개 (×100):
                쇼핑백    4PT → 부족 4PT×100
                G형박스   6PT → 부족 3PT×100
                눈마사지기 6PT → 부족 6PT×100
                미르텀블러 5PT → 부족 3PT×100
                키트포장  1PT → 부족 1PT×100
              ⇒ 총 17개 PT 발주 목록 자동 산출     ← 발주 액션
[S3 입하예측] 입하CBM ≈ 1.06m³ · M/H 1.31h       ← 도크/인력 준비
[S4 창고투영] staging 0.0% → 최대 1.6% (Max 57.6m³) — 여유 충분
[S5 배차]     출하CBM 3.57m³ → W1/W2/W3 전부 가능 (max 4.5/7.6/9.5)
[S6 운임]     ₩64,000~₩105,500 (수도권 거리대)
[S7 Ledger]   PropagationLedger INSERT — 전파상태 "부분" + 끊김 사유 기록
     ↓ TMS replay cron
[TMS Shipment] estimated_cbm 3.572 ✓ (cascade 산출 3.57과 일치 — 교차검증 통과)
[배차]         wave_recommendation · 차량이용률 KPI rollup 자동
[운임정산]     CBM 구간 요율 → 정산 파이프라인 자동 소비

IV어디서부터? — 기초공사 5단계 (SSOT-first)핵심

밑에서 위로 순서대로 쌓는다. 각 층은 아래 층이 있어야 성립한다.

L0
아이템 정체성 SSOT
하나의 품목 = 하나의 표준 정체성. 원자 단위 2종(굿즈·PT####). 코드 정합: 굿즈코드 ↔ PT#### ↔ 견적코드 ↔ SERPA → 1개 표준키.
왜: 모든 것의 뿌리 — 없으면 굿즈명 조인 53% 약점 발생 주도: 안나 위치: 신규 SSOT (백엔드 잠정)
L1
아이템 계층
완제품(굿즈) → 키트 → 구성품 → 부자재 → 포장재. 품목유형 분류(산출물·서비스 PT 구분 포함).
왜: 정체성 위 부모-자식 골격 주도: 안나 위치: 신규 SSOT (백엔드 잠정)
L2
BOM (소요량)
모품목 → 소품목 + 소요량_개당. order 그룹핑 부트스트랩 → 검증 승급.
왜: 계층 엣지에 수량을 매김 주도: 안나 위치: 신규 SSOT (백엔드 잠정)
L3
CBM (부피)
각 아이템에 부피 속성. 굿즈 CBM(박스규격) · 파츠 CBM(치수).
왜: 아이템 정체성에 부피 바인딩 주도: 물류 위치: Airtable (운영)
L4
수량전파 (cascade)
등록 → 폭발 → 소요 → CBM → 배차 → 운임마감 자동 흐름.
왜: L0~L3 완비 시 III장 비전 완결 주도: 물류 위치: Airtable (운영)

VI로드맵 순서핵심

기초공사 순서(L0→L4)를 그대로 일정화한다. 기존 물류 7~12월 작업(Chain)을 흡수한다.

P0
7월 W1
킥오프 · 정렬 (오늘 · 공동)비전(cascade 예시) 공유, 기초 5단계·SSOT 경계 원칙 합의, 로드맵+RACI 확정.
P1
7~8월
L0+L1 정체성·계층 (안나 주도)안나 주도 정체성 SSOT + 계층 + 코드 4종 정합. 물류가 crosswalk/BOM/CBM 시드·요구사항 제공.
P2
8~9월
L2 BOM (안나 주도)안나 주도 BOM 구조/소요량 설계. 물류는 부트스트랩 로직·시드 제공.
P3
9~10월
L3 CBM (물류 주도)아이템에 CBM 바인딩 (파츠 CBM 등록 포함).
P4
11~12월
L4 전파 · 통합 (공동)신 기초 위 project→운임 전체 흐름 재구축 + 스냅샷 대시보드(백엔드 잠정) + 연말 리뷰 · 2027 스코프.
