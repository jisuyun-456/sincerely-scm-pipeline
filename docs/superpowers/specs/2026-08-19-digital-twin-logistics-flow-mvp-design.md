# 디지털 트윈 물류 — 플로우 관측 MVP 설계

> **상태:** 설계 확정 (brainstorming 2026-08-19) · 다음: writing-plans
> **한 줄:** WMS·TMS·MES·IBSA에 흩어진 단계별 시각을 **하나의 정규화 이벤트 로그**로 모아, 7단계 물류 플로우의 **병목·리드타임·이벤트 공백**을 진단한다.

## 1. 배경 & 동기

CBM·BOM 개별 프로젝트만 파면 전체 흐름(flow)을 놓친다. 물류 전 과정을 **하나의 살아있는 모델**로 보기 위한 최소 디지털 트윈을 정의한다.

**결정적 발견 (2026-08-19 세션):** 프로세스 단계별 "언제·누가·얼마" 이벤트 타임스탬프가 불완전 — 특히 **프리패키징 완료 이벤트 부재**. M/H 일자별 집계 중 우연히 만난 이 갭이, 사실 시스템 전체의 관측 구멍이었다. 트윈은 새로 짓는 게 아니라 **이미 흩어져 있는 조각(상태·이벤트·시뮬·뷰)을 잇는** 문제다.

## 2. 북극성 & 스코프 (확정)

| 결정 | 값 | 근거 |
|---|---|---|
| **북극성** | 플로우 관측 = 진단 트윈 ("어디서 막히나·왜") | 이벤트 갭 인사이트와 직결 |
| **스코프** | 전체 7단계 (자재 플로우 + 오더 플로우 + 자재투입 핸드오프) | 큰 그림 우선 |
| **주력 뷰** | 단계별 체류시간 **병목 히트맵** | "어디서" 한눈에 |
| **보조 뷰** | 오더 타임라인(Gantt) · In-flight WIP 보드 | 이벤트 로그에서 파생, 후순위 |

## 3. 아키텍처: 통합 이벤트 로그 → 병목 히트맵

트윈의 심장 = **하나의 정규화 이벤트 로그.** 4개 베이스의 단계별 시각을 단일 스키마로 모은다.

### 이벤트 스키마
```
event = {
  entity_id,          # 엔티티 키 (PT코드 | 오더 PNA | Shipment SC)
  entity_kind,        # 'material' | 'order' | 'shipment'
  stage,              # 입하|검수|입고|자재투입|프리패키징|출하|배송
  event_ts,           # ISO KST (UTC 소스는 +9h 변환)
  qty, cbm,           # 선택 — 물량·부피
  source_base, source_rec_id
}
```

### 병목 히트맵 = 파생
연속 단계쌍마다 `dwell = ts(단계 N+1) − ts(단계 N)`, 인접 두 타임스탬프를 다 가진 엔티티에서 집계(중위·P90). **타임스탬프 없는 단계는 0으로 묵살 금지 → `측정불가`로 명시.** 그게 진단이다.

부트스트랩은 **기존 Airtable 상태필드에서 이벤트 역추출(ETL)** — 운영 변경 0으로 지금 큰 그림이 나오고, 갭은 "여기에 캡처를 넣어라" 지도가 된다.

## 4. 7단계 이벤트 맵 (실측 타임스탬프 가용성)

| # | 단계 | 진입 타임스탬프 | 소스 (base/table/field) | 가용성 |
|---|---|---|---|:---:|
| 1 | 입하 | 입하일자 / 실제입하일 | IBSA `app6DGHCP…/tblhzYilt…` `입하일자=fldcCmgZNTKUWpL9J` · WMS `flduN8khmYwdn7uVD` | ✅ 클린 |
| 2 | 검수 | 시안검수완료 | IBSA (입하완료→시안검수완료, inspect_time 소스) | ✅ |
| 3 | 입고 | GR/재고반영 | IBSA DTS · `ERP_재고반영일자` | ✅ |
| 4 | 자재투입 | 자재투입완료시간 | WMS `appLui4ZR…/tblwq7Kj…` `자재투입완료시간` (96% 타임스탬프) | ✅ |
| 5 | **프리패키징** | 프리패키징 완료 | — (WMS엔 없음) → **MES `appNSAPad…` 생산완료 프록시 조사** | ❌ **갭** |
| 6 | 출하 | 출하완료/출하일 | TMS `app4x70a8…` Shipment `TF_DATE=fldQvmEwwzvQW95h9` | 🟡 확인필요 |
| 7 | 배송 | 배송완료/POD | TMS delivery events | 🟡 확인필요 |

**킬러 인사이트 (트윈 첫날 산출):** 프리패키징 완료 이벤트 1개 부재로 **`투입→프패`·`프패→출하` 두 transition이 통째로 블라인드** — 하필 납기 압력이 몰린 출하측 구간. **단일 이벤트 갭이 플로우 최대 사각지대.**

## 5. 데이터 소스 & 저장소

**소스 = 베이스별 추출기 1개씩** (IBSA·WMS·TMS·MES). 각 상태 date-field → 정규화 이벤트 emit. UTC 소스는 KST(+9h) 변환.

**저장소 = git-버전 계산 스냅샷** — `data/twin/events-<period>.jsonl` + 집계 `flow-<period>.json`. 운영 SSOT는 Airtable 유지, 이벤트 로그는 **파생 projection**(매 실행 재계산)이라 주간리포트 `history/reports/` 패턴 재사용. Supabase 정책·git-SSOT 선호와 정렬.

**케이던스:** 기존 GitHub Actions에 붙여 주간(또는 일) 재계산.

## 6. 엔티티 조인 / 핸드오프 (실현가능성 급소)

7단계 관통 단일 키 **없음** — 2개 서브플로우가 자재투입에서 만남:
```
자재플로우 (PT키)     입하→검수→입고 ─┐
                               자재투입 ← 두 키를 다 든 브릿지 이벤트
오더플로우 (PNA/SC키)     프패→출하→배송 ─┘
```
- 병목 히트맵은 **aggregate**라 완전한 end-to-end 스레딩 불필요 — transition별로 joinable 레코드쌍에서 dwell 계산.
- 까다로운 조인(`입고→투입`·`투입→출하`)의 오더측 키 = **병렬 진행 중인 브릿지 크로스워크(bridge-cbm-ssot)가 공급** → 두 프로젝트 상호보강.
- end-to-end 오더 스레딩 = stretch goal (MVP 아님).

## 7. MVP 산출물

1. **병목 히트맵** (헤드라인) — transition별 dwell 중위·P90 + RAG + `측정불가`. **기존 Pages 대시보드 "플로우 진단" 페이지/섹션** (주간리포트 MD+HTML 파이프라인 재사용).
2. **갭 리포트** — 측정불가 단계·transition + 커버리지% (트윈 자기진단 = 캡처 우선순위 지도).
3. **보조(후순위):** 오더 타임라인 drill-down · In-flight WIP 보드.

MVP 코어 = **1 + 2.**

## 8. 스코프 아웃 (YAGNI)

- 新 이벤트 캡처 레이어(운영 입력변경) — MVP는 기존 필드 역추출, 캡처는 갭 리포트가 정당화하는 **후속**.
- What-if 시뮬레이션 / MRP 예측·처방 — 후속 트윈 성숙도 단계.
- 실시간 스트리밍 — 배치 재계산으로 충분.
- 프리패키징 갭 **메우기** — 트윈은 **드러내기**만 (메우기 = 프리패키징 완료 타임스탬프 필드 신설, 별도 액션).

## 9. 성공 기준

1. 4개 베이스 → 통합 이벤트 로그 생성, 7단계 중 **≥5단계** 실측 타임스탬프로 채워짐.
2. 병목 히트맵이 transition별 dwell(중위·P90) 산출, **측정불가 2건(투입↔프패↔출하)을 명시적으로 플래그**.
3. 갭 리포트가 커버리지%와 프리패키징 갭을 최우선 캡처 대상으로 지목.
4. git 스냅샷 재계산 결정론(같은 Airtable 상태 → 같은 이벤트 로그).
5. Pages 대시보드에 "플로우 진단" 렌더 + AI분석용 MD 동시 산출.

## 10. 리스크 & 오픈 이슈

- **출하·배송 타임스탬프(6·7) 미확인** — TMS Shipment/delivery 필드 실측 검증이 구현 1순위.
- **입고↔투입 PT 조인** — WMS movement 자재투입이 IBSA 입고 레코드와 매칭되는 키 확인 필요.
- **MES 프리패키징 프록시** — 생산완료 타임스탬프가 프리패키징 완료의 유효 프록시인지 조사(성공 시 갭 부분 해소).
- **엔티티 kind 혼재** — material/order/shipment 키 네임스페이스 분리 유지(브릿지 크로스워크 재사용).
