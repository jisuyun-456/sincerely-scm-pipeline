## 1. CBM 분석

### 1.1 산출 커버리지
- **추정 CBM 산출 1841 / 2607 (70.6%)**. 분포: min 0.0098 / median 0.588 / max 196.0 m³.
- **CBM 계산식은 정합** — 값이 주문수량에 선형 비례, 이상치 없음. 상위 CBM은 전부 *실제 대량주문*:
  - 196 m³ = Solid 커스텀 G형박스 ×16,000 (PNA52044) — 0.012 m³/개, 정상.
  - 44.3 m³ = 더블업 트래블 파우치 ×2,000 등.
  - **단일 출하 W3(9.486 m³) 초과 26건** → CBM 버그 아님, **분할/외주 필요 물류 플래그**(올바른 신호).

### 1.2 S3 입하 part CBM — **최대 단일 문제 (V1)**
- **2013단위(77.2%) 차단**, 고유 미산출 PT **1030종**.
- 근본: `WMS_ItemMaster.CBM_개당_m3` ← `sync_parts` 규격(치수) 결손. 코드/파서 문제 아님.
- **롱테일** (집중도 낮음):

| top-N PT 치수 입력 | S3 완전해소 단위 | % of S3-blocked |
|---|---|---|
| 20 | 286 | 14.2% |
| 50 | 441 | 21.9% |
| 100 | 714 | 35.5% |
| 200 | 995 | 49.4% |

- S3 차단 단위 중 **단일 PT 의존 736(36.6%)** — 이들은 PT 1종만 치수 들어와도 즉시 해소.
- 빈출 PT: PT4424(100)·PT4421(92)·PT3708(63)·PT4894(63)·PT4432(63)·PT3576(60)·PT4422(60)·PT2402(58)·PT4464(56)…
- **레버리지:** top-100 PT 치수 입력 → S3 차단의 35% 해소 → 완결률 13.8% → ~40%대 추정. 유일 구조해법 = SERPA→sync_parts 규격에 가로×세로×높이 입력.

### 1.3 S5 출하 CBM
- 791단위(30.3%) 차단이나 **603(76%)은 `partial_skip` = 다차출하 프로젝트의 의도된 중복합산 방지**(설계상 정상, 결함 아님).
- 순수 `deterministic` 미산출 162단위 중:
  - **서비스코드 잔여 58** (SSSV 등) → §1.4
  - **실품목 코드갭 99단위 / 46종** → ③/④ 박스데이터 대상. 빈출: BSPK(9)·OFMP(7)·ATWK(6)·TCMP(6)·UMUG(6)·WSPB(5)·OMMG(4)·MIST(3)…
  - ⚠️ 엣지: `VMCM/VMCS`(각 3), `STNB`(2)가 등록코드인데 직접 미산출 → qty=0 또는 Product CBM 0 케이스 점검 필요(소량).

### 1.4 🟡 V5 서비스 필터 공백변형 누락 (신규 발견 — 내 V5 후속 필요)
H1 광역 윈도우에서 V5 필터가 놓친 변형 발견 (window46 검증엔 없던 표기):
- **"키트 포장"(공백 있음) 53단위** — V5는 `"키트포장"`(공백 없음)만 매칭. 공백 변형 누락.
- **"긴급 제작"(공백 있음) 4단위** — V5는 `"긴급제작"`만 매칭.
- **"1222"·"1231" 등 10~12월 날짜형** — V5 정규식 `^0\d{3}$`는 1~9월(0XXX)만. 10~12월(1XXX) 누락.
- **"보관"** 1단위 — placeholder.
→ **수정안(V5.1):** is_service에서 공백 정규화(매칭 전 공백 제거) + 날짜형을 유효 MMDD(`^(0[1-9]|1[0-2])\d{2}$`)로 확장. 과필터 가드 재검증 필수.

## 2. BOM 분석

### 2.1 S2 BOM행 없음 — 74단위(2.8%), 🟡 재제작 명명 갭
- **고유 60종 중 ~90%가 `_재제작`·`_추가제작`·`_재재제작` 접미** 주문:
  - 아트워크레더다이어리_재재제작(4)·미스트워터보틀_재제작(3)·베케이션여권케이스_재제작(3)·테크미니파우치_재제작(3)·레더스킨다이어리(표준)_재제작(3)…
- 근본: `select_bom_rows`가 `모품목_굿즈명 == goods_name` **정확매칭**. 재제작 주문은 굿즈명에 접미가 붙어 베이스 BOM행과 불일치 → BOM 없음 폴백도 실패.
- `normalize_goods`는 `_접미`를 제거하지만 **collect_units·select_bom_rows는 normalize를 적용 안 함**(parse_goods만).
- **수정안(V3.1):** BOM 매칭 시 재제작/추가제작 접미·`(...)`·`[n]`를 정규화 후 베이스 굿즈명으로 대조. ⚠️ 재제작 BOM이 베이스와 다를 수 있어 "베이스 폴백"으로만(검증상태 미검증 태깅).
- 잔여 비-재제작: 날짜/숫자 placeholder("1231","300") → V5.1로 흡수, 괄호/인덱스 변형 소수.

### 2.2 BOM 검증 신뢰도 (V3, 구조)
- 리포트로는 검증상태가 안 보이나, 기지값 **검증완료 6.9%(117/1702)**. MRP는 미검증행도 소비 → **부족자재 산출은 되나 신뢰도 낮음**.
- 액션: `scripts/backbone/task_bom_verify.py` 재실행으로 task 실적분 검증완료 승급(코드로 가능).
