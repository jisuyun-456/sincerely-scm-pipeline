# 굿즈코드 적용 시 파이프라인 영향 검토 (2026-06-17)

> 목적: TMS Product에 굿즈코드를 등록/변경할 때, **운임정산(기사님)·배차추천** 자동화가 어떻게 반응하는지 + 계산수식 분기를 명시. 사용자 우려("적용 계산 수식 로직이 다를 것") = **사실로 확인**.
> 근거: 실제 코드 추적(path:line) + 스키마 조회. 본 문서는 읽기 전용 산출(코드 변경 0).

---

## 0. 한 줄 결론

굿즈코드를 Product에 등록하면 **캐스케이드·배차(코드 기반)**는 정합되지만, **운임정산 상하차비는 코드가 아니라 품목'명' 매칭**으로 CBM을 끌어온다. 그래서 코드만 맞추는 규율로는 정산 경로가 안 고쳐진다 → 본 task에서 정산을 **공유 리졸버**로 통일(이름→sync_item 코드→alias→Product). 거리운임·고정일급은 굿즈코드와 무관.

## 1. 파이프라인별 CBM/운임 계산 분기

| | 캐스케이드 S5 / `wave_recommender`(배차 prod) | 운임정산 상하차비(prod) | `dispatch_advisor`(virtual_sap **시뮬레이션**) |
|---|---|---|---|
| CBM 키 | 굿즈**코드** → Product + **V2 alias** | 품목**명** → Jaccard(≥0.4) → Product, **alias 미적용** | 측정 `total_cbm` 직접 (룩업 없음) |
| 수식 | `ceil(qty/qty_per_box)×cbm_per_box` | box-type 버킷 요금 (※ box_text 없을 때만 발동) | 필드값 그대로 |
| 신선도 | **24h 캐시**(product_loader) | **라이브**(<1s) | n/a |
| 굿즈코드 등록 영향 | **O** (캐시 만료 후) | 이름 매칭 통해 **간접** | **X** |
| 거리운임(박종성 haversine·이장훈/조희선 고정일급) | — | **굿즈코드 무관** | — |

**dispatch_advisor는 실배차 아님** — `harness/virtual_sap/`(SAP 시뮬레이션). 실제 배차 추천 엔진은 `wave_recommender`.

## 2. 검증된 사실 (path:line)

- **운임정산 상하차비 = 품목명 매칭:** [harness/tms_settlement/calc.py:222-230](../harness/tms_settlement/calc.py#L222-L230) → `calc_from_products(items_text, ...)`, 내부 [harness/settlement/cbm_calc.py:218](../harness/settlement/cbm_calc.py#L218) `match_product`(Jaccard). **굿즈코드·V2 alias 미사용.** `if not box_text`일 때만 발동(3단 폴백) — box_text 있으면 박스파싱 직접.
- **박종성 거리운임:** [harness/tms_settlement/calc.py:250-252](../harness/tms_settlement/calc.py#L250-L252) `round_up_500(park_base + park_km × haversine × road_factor)` — 굿즈코드 무관.
- **이장훈/조희선:** 고정일급 ÷ 건수 (+경기 할증) — 굿즈코드 무관. [calc.py:129-172](../harness/tms_settlement/calc.py#L129-L172).
- **배차 실엔진:** [harness/dispatch/wave_recommender.py](../harness/dispatch/wave_recommender.py) (cron 09/14/17 KST) + [harness/dispatch/cbm_estimator.py:248](../harness/dispatch/cbm_estimator.py#L248) `estimate_shipment_cbm_deterministic`(코드→Product). DRIVER_LIMITS 용량 체크.
- **캐스케이드 S5:** [harness/backbone/cascade.py:391-394](../harness/backbone/cascade.py#L391-L394) 동일 estimator + V2 alias remap([product_alias.py](../harness/backbone/product_alias.py)).
- **Shipment에 견적코드 필드 없음:** TMS Shipment(tbllg1JoHclGYer7m)는 품목'명' 텍스트(임가공 품목·최종 출하 품목)만 보유, Product 링크 없음 → 단일 견적코드 필드 구조적으로 불가. → 정산 통일은 스키마 변경 없이 **공유 리졸버**(이름→코드→alias→Product)로 해결.

## 3. 굿즈코드 등록 시 latency 비대칭

| 경로 | 반영 시점 |
|---|---|
| 운임정산 상하차비(`calc_from_products`, 라이브 쿼리) | **<1s** (즉시) |
| 캐스케이드·배차(`product_loader` 24h 캐시) | **최대 24h** |

→ Product에 코드 등록 직후, 정산 상하차비는 즉시 반영되지만 배차/캐스케이드는 다음 캐시 갱신(최대 1일)까지 지연. 운영 시 인지 필요.

추가: **수동 `Shipment.Total_CBM` 입력 시 모든 추정 무시**(estimate confidence=1.0, mode='실측'). 오입력 시 운임·배차·M/H 전부 오염되며 다운스트림 검증 없음.
