## P2-a. task↔BOM 검증률 6.9% — 근본원인 = 구조 불일치 (정규화 버그 아님)

### 측정 (live, 2026-06-17)
- task 5375행 → (PNA,PT) 쌍 1207 / PNA종 632 / **PT종 154**
- BOM 1702행 / 이송(미검증) 1585 / 키없음 0
- **PNA 교집합(매칭 상한): 947** — task에 그 프로젝트 자체가 있는 이송행
- raw 매칭(현행): **1** / extract_pt 정규화 매칭: **1** (동일)
- BOM 소품목_PT: 1585행 전부 `raw == extract_pt` (예 'PT1285','PT2093') → **정규화 불일치 없음**

### 가설 기각 + 진짜 원인
- ❌ **정규화 버그 가설 기각**: BOM `소품목_PT`는 이미 깨끗한 `PT####`. `extract_pt`로 정규화해도 매칭 1→1 변화 없음. → `select_bom_promotions` 코드 수정해도 검증률 안 오름.
- ✅ **진짜 원인 = BOM 레벨 불일치**:
  - task `생산공정_투입자재 (from order)` = **굿즈 레벨** PT (예 `PT2405-베케이션여권케이스`, `PT2969-메시지캐리어파우치`)
  - BOM `소품목_PT` = **소품목(하위 부자재) 레벨** PT (예 `PT1285` bare)
  - task `이전공정_투입자재` = 자재 **이름**만(`배경지(기본)`, `미르텀블러(블랙12oz)`) — PT코드 없음
  - 같은 프로젝트(947행 PNA 교집합)라도 task가 가리키는 부품 ≠ BOM 소품목 → 1건만 우연 일치.
  - task 투입자재 충진: 5375행 중 비어있지않음 1730 / PT코드 1개+ 1137 (전체의 21%).

### 결론
- "검증률 6.9%↑"는 **task↔BOM (PNA,PT) 매칭으로는 코드로 달성 불가** (설계상 두 측이 서로 다른 BOM 레벨 참조). 6.9%(검증완료 117/1702)는 타 경로 사전검증 베이스라인이며 유지.
- **거짓 승급 금지**: PT-only/loose 매칭으로 억지 상승시키면 "프로젝트가 그 소품목을 실제 소비했다"는 증거 없는 false 검증완료 → Immutable Ledger 정신 위배.
- **진짜 레버(향후, P2 범위 밖)**: 소품목 레벨 소비 증거원 = movement 261(생산출고) 또는 MES 소비 로그로 BOM 소품목 대조. 별도 phase 후보.
